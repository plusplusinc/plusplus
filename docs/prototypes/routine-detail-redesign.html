What each of these costs to build

⚠ decide first

The title hand-off has two routes

Giving detail the system navigation bar with a large title buys Today's collapse for free and writes no state. But a system large title does not wrap, and single-line truncation is exactly what build-78 moved the name into the body to fix.

So the prototype hand-rolls it: two-line wrap kept, crossfade driven by a pure render-time visualEffect. That matters — an onGeometryChange or a PreferenceKey write anywhere in the TabView subtree breaks the search-role morph.

⚠ rail geometry

Two-line names break uniform rows

RailLayout assumes one railRowHeight for every row, and the drag, ring and drop targets all read it. A wrapping name makes rows variable-height.

Cheapest correct answer: keep rows uniform and raise the height to fit two lines at body size, so nothing in RailArrangement changes. Teaching the layout per-row heights is the honest fix and a much bigger diff — worth its own issue.

The two-column ledger makes this easier, not harder: every row is a two-line block regardless of name length, so one raised constant covers the whole rail.

And the node moves off the row's midpoint. RailGlyph is handed dotY: rowHeight / 2, which is right only while a row is one line — with a wrapping name it lands in the gap between the two lines. It becomes the first line's centre: top padding plus half a line, both @ScaledMetric so it tracks Dynamic Type. The superset loop's quarter-curves read the same dotY, so they follow for free.

corrected

The ledger does fit

The first pass here claimed a two-column ledger could not sit beside the rail at phone width. That measured a cell holding 3×10–15 · 35lb on one line, at ~90 pt.

One run per line — reps above weight, which is what DiffLedger already does for multi-run cells — puts the column at 58 pt. Two of them plus the 41 pt rail leave the name ~160 pt, enough for the longest name in this routine at two lines. The row is a fixed two-line block either way, which is convenient for the rail geometry below.

prev already exists

Today's card builds its rows from ledger(for:) in TodayView, over RoutineDiff and Prescription.blockRuns(prior:). Detail needs the same producer, so it moves out of TodayView into a shared place beside RoutineCardContent and both surfaces read it.

That also gets the ledger's rules for free: no green, no delta, prev flat, and the stacked reflow at accessibility sizes.

One ignition, two call sites

The welcome key's wipe, label morph and chevron march live inside IntroView. Lifting them into the shared StartFlashButton gives routine detail the full sequence and changes Today's Start too, since both call it.

Worth wanting: one start gesture across the app. Flagging it because it is not only this screen.

What the chips do not take

Focus, estimate, exercise and set counts are computed from the exercises — there is nothing to open, so they stay text. Effort only exists on catalog templates.

Rename, transition and delete stay in settings whichever option wins; the chips add a second door, they do not empty the room.

⚠ device pass

None of this is CI-visible

Scroll-driven chrome, a sticky band and a leading-reveal rail all live below XCUITest, which dispatches through accessibility and skips gesture overlays. The rail already carries a leading DUPE reveal under leadingRevealHost; a taller row changes the drag distances it arbitrates against.
